DSL syntax


VAR name: DATE | NUMBER | MONEY | BOOL | ENUM(A, B, C);
STATE NAME [INITIAL];
RULE id FROM STATE: IF cond THEN ACTION(args) [UNLESS cond] [GOTO STATE];
# comment

      
Expressions: OR < AND < NOT < comparison (> < >= <= == !=) < + -. Durations: 30 DAYS;
         date + n MONTHS uses calendar months (month-end clamps).

      
Actions: PENALTY(n), WAIVE_PENALTY(), TERMINATE(). Types: MONEY and NUMBER compare; DATE ± DURATION → DATE;
         DATE − DATE → NUMBER (days). ENUM supports == and != against its own literals.

      
Stages: lexer, recursive-descent parser, semantic analysis (E2xx), FSM, static analysis (reachability BFS, conflict
         detection on effective conditions, Tarjan SCC cycles), bytecode, stack VM.

      
Bytecode: PUSH LOAD STORE ADD SUB ADD_MONTHS SUB_MONTHS CMP_EQ/NE/LT/GT/LE/GE AND OR NOT JUMP JUMP_IF_FALSE CHECK_STATE
         TRANSITION TRIGGER_OBLIGATION RULE HALT. Validated (operands, jump targets, stack depth and types) before execution.

      
Limitations: conflict analysis is exact only for conjunctions of var OP number / BOOL guards (others give
         warnings); the VM evaluates rules in one pass in source order; cycles are structural and never proven infinite; no legal
         validity checking. See docs/LIMITATIONS.md.
